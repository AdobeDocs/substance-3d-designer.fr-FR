# Découvrez les termes et concepts utilisés dans Designer.

## #&#x200B;

|  |  |
| --- | --- |
| <b><span id="three-d-scene"></span>Scène 3D</b> | Collection d’objets et de données impliqués dans la représentation et l’animation d’une visualisation de l’espace 3D :<ul data-preserve-html="true"> <li data-preserve-html="true">[Maillages](#mesh)</li> <li data-preserve-html="true">[Matières](#material)</li> <li data-preserve-html="true">Caméras</li> <li data-preserve-html="true">Lumières</li> <li data-preserve-html="true">Animation</li> <li data-preserve-html="true">Simulations</li> <li data-preserve-html="true">...</li> </ul>[Les formats de fichiers les plus populaires](https://www.adobe.com/fr/products/substance3d/discover/3d-files-formats.html) pour stocker des scènes 3D incluent [USD](#usd) de Pixar et FBX d&#39;Autodesk. Tous les formats de fichiers ne prennent pas en charge tous ces composants |

## A

|  |  |
| --- | --- |
| <b><span id="alpha"></span>canal Alpha</b> | Quatrième couche d’une image couleur, souvent utilisée pour décrire l’opacité. |
| <b><span id="ambient-occlusion"></span>occlusion ambiante</b> | L&#39;atténuation de la lumière ambiante sur les surfaces moins exposées et donc plus difficiles à atteindre. |
| <b><span id="anisotropy"></span>Anisotropie</b> | Propriété d&#39;être dépendant de la direction. En d’autres termes, fournir un résultat différent lorsqu’il est mesuré ou observé sur un axe différent.   Les matériaux anisotropes ont un aspect différent selon leur origine, et les filtres anisotropes ne sont pas appliqués uniformément dans toutes les directions. |
| <b><span id="api"></span>API</b> | Une interface de programmation d&#39;application (API) est un ensemble de fonctions et de procédures qui permet aux utilisateurs d&#39;accéder aux fonctions et aux procédures d&#39;une autre application de programme.   Une API fournit une couche contrôlée et sécurisée entre l’utilisateur et un programme. Il peut également utiliser un autre langage de programmation pour rendre ce programme plus facile à interagir et plus largement accessible.   Designer propose une [API Python](../scripting/scripting.md) qui fournit un accès facile à un large éventail de ses fonctionnalités pour la manipulation des données, la création d&#39;outils personnalisés et l&#39;accélération des workflows. |
| <b><span id="atomic-node"></span>Nœud atomique</b> | Composantes fondamentales des graphiques. Tous les [nœuds d&#39;instance](#instance-node) peuvent être décomposés en graphiques de nœuds atomiques. Chaque type de graphe possède son propre ensemble de nœuds atomiques. |

## B

|  |  |
| --- | --- |
| <b><span id="baking"></span>Cuisson</b> | Processus consistant à calculer des informations à partir d&#39;un modèle 3D et à stocker les résultats dans une [texture](#texture). Les données sont placées dans la texture en fonction des [UV](#uv) du modèle. |
| <b><span id="base-color"></span>Couleur de base</b> (Albédo) | Canal d&#39;un [matériau](#material) défini à l&#39;aide du modèle de rugosité métallique PBR [ombrage](#shader). La couleur de base spécifie la couleur d’une surface sans aucune information d’éclairage.   Il ne doit pas être confondu avec [Diffuse](#diffuse). |
| <b><span id="base-parameter"></span>Paramètre de base</b> | Paramètre commun à tous les nœuds d&#39;un graphique de Substance qui calculent un [bitmap](#bitmap).   Il s&#39;agit notamment des aspects fondamentaux de l&#39;image bitmap, tels que sa résolution ([taille de sortie](#output-size)) et son [nombre de bits par pixel](#bit-depth) (format de sortie), ou la façon dont l&#39;image bitmap est calculée, par exemple en mode [mosaïque](#tiling).   Les paramètres de base sont souvent [hérités](#inheritance) d&#39;autres nœuds en amont ou du graphique hébergeant le nœud. |
| <b><span id="bilinear-filtering"></span>Filtrage bilinéaire</b> | Processus d&#39;interpolation utilisé en imagerie informatique lorsqu&#39;un [échantillon de texture](#texture-sampling) n&#39;est pas effectué exactement au centre d&#39;un pixel.   Par exemple, cela peut se produire lorsqu’une image est agrandie. |
| <b><span id="bit-depth"></span>Nombre de bits par pixel</b> | Nombre de bits utilisés pour stocker la valeur d’un pixel dans une texture. Des nombres de bits par pixel plus élevés permettent de coder davantage de valeurs, ce qui produit des dégradés plus lisses.   Différents nombres de bits par pixel sont disponibles selon le type de valeur : - Les valeurs entières peuvent être codées en utilisant 8 bits (0 à 255) ou 16 bits (0 à 65 535). - Les valeurs à virgule flottante peuvent être codées à l’aide de 16 bits (+32767,9999 à -32768,0) ou de 32 bits (-3,4E+38 à +3,4E+38) Les images à plage dynamique faible utilisent des valeurs entières pour coder les étapes de 0 à 1. Les images de plage dynamique élevée utilisent des valeurs à virgule flottante pour coder des valeurs numériques brutes.   Dans les graphiques de Substance, le nombre de bits par pixel est contrôlé par le paramètre Format de sortie. |
| <b><span id="bitmap"></span>Bitmap</b> | Une image numérique. Deux types d’images sont les plus courants :<ul data-preserve-html="true"> <li data-preserve-html="true">Les images en niveaux de gris n&#39;ont qu&#39;une seule couche : luminance (L);</li> <li data-preserve-html="true">Les images couleur comportent trois couches : rouge, vert et bleu (RGB). Un quatrième peut être présent: alpha (A) qui est souvent utilisé pour l&#39;opacité. Les images couleur dans Designer sont toujours RVBA.</li> </ul>  Les bitmaps sont généralement considérés comme des grilles de valeurs. Chaque cellule de cette grille est un pixel, ce qui est abrégé en « élément d’image ». Un pixel stocke une valeur par couche. Le type de cette valeur dépend du [nombre de bits par pixel](#bit-depth) du bitmap. |

## C

|  |  |
| --- | --- |
| <b><span id="cache"></span>Cache</b> (Mémoire) | Une collecte de données - Par ex. [paramètres de base](#base-parameter) du nœud et images de sortie - stockés en mémoire pour être réutilisés.   Le cache accélère considérablement les calculs graphiques en laissant la [Substance Engine](#substance-engine) recalculer uniquement les parties d&#39;un graphique qui ont changé. Lorsque vous ajustez les connexions et les paramètres des nœuds, tous les nœuds qui les précèdent ne sont pas affectés par ces modifications. Il n&#39;est donc pas nécessaire de les [évaluer](#evaluation) à nouveau pour mettre à jour le graphique. Leur cache est utilisé à la place.   Le cache peut avoir une empreinte mémoire importante lors de l’utilisation de résolutions et de résolution élevées dans les graphiques volumineux. |
| <b><span id="channel-packing"></span>packing de canal</b> | Technique d’optimisation consistant à compresser des images séparées dans les couches du RGB (A) d’une seule image couleur.   Par exemple, une texture RMA est une texture de rugosité (R), de métallisation (M) et d&#39;occlusion ambiante (A) regroupées dans une seule texture de couleur.   Une autre technique courante consiste à packing une texture en niveaux de gris dans la couche bleue d&#39;une texture normale, car la couche bleue, c&#39;est-à-dire le composant « Up » du vecteur normal, peut être recalculée lors de l&#39;exécution.   Le nœud [Fusion RVBA](../compositing-graphs/nodes-reference-for-com/node-library/filters/channels/rgba-merge/rgba-merge.md) est utile pour mettre en œuvre cette technique. |
| <b><span id="color-space"></span>Espace colorimétrique</b> | Définition de la représentation d’une plage de couleurs. Le codage et le décodage numériques d’une couleur spécifique nécessitent une telle définition pour donner un sens aux nombres utilisés.   Un fichier d’image stocke les valeurs de couleur à l’aide d’un espace colorimétrique spécifié, afin que ces couleurs puissent être fidèlement reproduites sur un écran prenant en charge cet espace colorimétrique. Un écran dispose de capacités de reproduction des couleurs spécifiques qui lui permettent de prendre en charge entièrement ou partiellement un espace colorimétrique donné.   Données brutes - Par ex. Une carte normale est toujours codée et décodée dans un espace colorimétrique linéaire, car ces couleurs ne sont pas destinées à être visualisées et aucune transformation ne doit être appliquée à ces données.   sRVB est un espace colorimétrique largement pris en charge. Les autres espaces colorimétriques populaires sont Adobe RGB, Rec. 2100 et ProPhoto RGB. |
| <b><span id="cooking"></span>Cuisson </b>(<span id="compilation"></span>Compilation) | Processus consistant à traduire des données dans une autre langue afin qu&#39;elles puissent être exécutées rapidement et efficacement. Le calcul du résultat d’un graphique de Substance nécessite au préalable sa compilation. La compilation fait partie du processus d&#39;[évaluation](#evaluation) du graphique.   Cette compilation est effectuée sur un graphique aplati, ce qui signifie que tous les [nœuds d&#39;instance](#instance-node) sont &#39;remplacés&#39; par leurs graphiques source de sorte qu&#39;il reste un graphique plus grand. C&#39;est ce graphique qui est compilé.   Un graphique compilé n’est pas modifiable. Les paramètres exposés restent disponibles s&#39;ils sont [dynamiques](#dynamic-parameter), tandis que les paramètres [statiques](#static-parameter) sont verrouillés et masqués. |
| <b><span id="culling"></span>Abattage</b> | Technique d’optimisation du rendu de scènes 3D qui supprime la géométrie des calculs du rendu lorsqu’elle n’est pas visible.   Cela peut inclure des objets ou des polygones en dehors du tronc de cône de l&#39;appareil photo (*abattage du tronc de cône*), orientés à l&#39;opposé de l&#39;appareil photo (*abattage du dos*) ou complètement masqués par d&#39;autres objets opaques (*abattage de l&#39;occlusion*). |

## B

|  |  |
| --- | --- |
| <b><span id="dependency"></span>Dépendance</b> | Un fichier A qui est utilisé par un autre fichier B de telle manière que le fichier B ne fonctionne pas comme prévu lorsque le fichier A est manquant.   Une dépendance d&#39;un [package](#package) peut être un autre package, car il référence un graphique à l&#39;intérieur, un fichier image, une police, etc. Un package stocke le chemin d&#39;accès à sa dépendance et un avertissement est généré si la dépendance est introuvable dans ce chemin. Les dépendances manquantes peuvent également entraîner la présence de [nœuds d&#39;instance fantômes](#ghost-instance-node) dans un graphique. |
| <b><span id="diffuse"></span>Diffus</b> | Canal d&#39;un [matériau](../glossary/glossary.md) défini à l&#39;aide du modèle PBR Specular Glossiness [ombrage](#shader). Diffus indique la couleur d’une surface lorsqu’elle est éclairée.   Il ne doit pas être confondu avec la [couleur de base (Albédo)](#base-color). |
| <b><span id="directx"></span>DirectX</b> | Collection d’API pour la gestion de contenu multimédia. Son API 3D, Direct3D, est largement utilisée dans le développement de jeux vidéo et d’autres industries 3D.   Direct3D place l&#39;origine d&#39;une texture, c&#39;est-à-dire sa coordonnée (0, 0), en *haut à gauche*, (Y-bas), tandis que l&#39;API [OpenGL](#opengl) la place en *bas à gauche* (Y-haut).   Cela signifie qu&#39;une carte de normales de DirectX a un *canal vert inversé* par rapport à OpenGL. En effet, le canal vert héberge la coordonnée Y des vecteurs normaux. |
| <b><span id="displacement"></span>Displacement</b> | Processus consistant à déplacer les [sommets](#vertex) d&#39;un modèle 3D, souvent le long de leur [normale](#normal).   Le displacement est souvent utilisé en association avec la [facettisation](#tessellation) et les [cartes de normales](#normal-map) pour modéliser des détails plus fins sur une surface. |
| <b><span id="dynamic-parameter"></span>Paramètre dynamique</b> | Paramètre dont la valeur peut changer. En d&#39;autres termes, tout paramètre dont la valeur n&#39;est pas constante est dynamique.    Cela inclut les paramètres exposés, tous les paramètres affectés par un paramètre exposé et toute valeur de paramètre affectée par [l&#39;échantillonnage dans une texture](#texture-sampling).   Contrairement aux [paramètres statiques](#static-parameter), la valeur des paramètres dynamiques peut être ajustée à la volée après la compilation du graphique dans un fichier SBSAR. |

## E

|  |  |
| --- | --- |
| <b><span id="evaluation"></span>Évaluation</b> | Processus de résolution de la propagation des données et des paramètres dans le graphique. L&#39;évaluation vérifie la validité d&#39;un graphique et de ses connexions, applique [l&#39;héritage](#inheritance) et [cuisine](#cooking) le graphique.   Dans la vue Graphique, une connexion est représentée par une ligne pointillée lorsqu’elle n’est pas évaluée. L&#39;évaluation transforme la connexion en lignes pleines.    Chaque fois qu&#39;un paramètre est ajusté dans un graphique, le nœud hébergeant ce paramètre et tous les nœuds en aval sont [invalidés](#invalidation) et doivent être réévalués avant d&#39;être [rendus](#rendering). |

## F

|  |  |
| --- | --- |
| <b><span id="filter"></span>Filtre</b> (Nœud) | Nœud qui applique une modification à une image (par exemple une déformation) ou en extrait des informations (par exemple un masque). |

## V

|  |  |
| --- | --- |
| <b><span id="ghost-instance-node"></span>Nœud d&#39;instance fantôme</b> | Un [nœud d&#39;instance](#instance-node) faisant référence à un sous-graphe introuvable, c&#39;est-à-dire une [dépendance](#dependency) manquante, est chargé en tant que nœud d&#39;instance fantôme.   Les nœuds d&#39;instance fantôme sont restaurés à l&#39;état attendu en résolvant la dépendance manquante et en rechargeant le [package](#package). |
| <b><span id="glossiness"></span>Lustre</b> | Canal d&#39;un [matériau](../glossary/glossary.md) défini à l&#39;aide du modèle PBR Specular Glossiness [ombrage](../glossary/glossary.md). La brillance spécifie la rugosité d&#39;une surface, c&#39;est-à-dire les variations microscopiques de l&#39;height, également appelées *microfacettes*.   Un brillant élevé donne un aspect lisse, tandis qu’un brillant faible donne un aspect mat et rugueux.   C&#39;est l&#39;inverse de la [rugosité](#roughness). |

## H

|  |  |
| --- | --- |
| <b><span id="histogram"></span>Histogramme (image)</b> | Dans le contexte d’une image, un histogramme représente la population des valeurs dans une plage donnée, souvent [0, 1].   Ce remplissage est visualisé à l’aide de barres verticales où une valeur plus présente dans l’image entraîne une barre plus élevée pour cette valeur. Les barres sont réparties horizontalement entre les valeurs basses (foncées) et les valeurs élevées (claires).   Les histogrammes des images couleur chevauchent généralement les histogrammes de chacune de leurs couches, généralement R, V, B. |

## I

|  |  |
| --- | --- |
| <b><span id="inheritance"></span>Héritage</b> | Dans le cadre des graphes de Substance, l&#39;héritage décrit la propriété des nœuds qui acquièrent des valeurs de paramètres à partir de leurs nœuds en amont ou de leur graphe parent.   Les paramètres hérités incluent la [résolution](#resolution) ([taille de sortie](#output-size)), la [profondeur de bits](#bit-depth) ([format de sortie](#output-format)) et le mode [mosaïque](#tiling).   En savoir plus sur l&#39;héritage dans cette [page dédiée](../compositing-graphs/inheritance-compositing/inheritance-in-substance-compositing-graphs.md). |
| <b><span id="instance-node"></span>Nœud d&#39;instance</b> | Un nœud d&#39;instance représente un graphe A dans un autre graphe B. Dans ce cas, le graphique A peut être appelé un [sous-graphe](#subgraph) du graphique B. Toute modification apportée au graphique A est propagée à tous les nœuds d&#39;instance qui la représentent.   Le nœud d&#39;instance applique son propre jeu de valeurs pour les paramètres d&#39;entrée du graphe A dans le contexte du graphe B. En ce sens, le graphique B peut héberger plusieurs nœuds d’instance qui font tous référence au graphique A, mais qui transmettent des valeurs ou des textures différentes en tant qu’entrées dans le graphique A.   Tous les nœuds de la bibliothèque Designer qui ne sont pas des [nœuds atomiques](#atomic-node) sont des nœuds d&#39;instance. |
| <b><span id="invalidation"></span>Invalidation</b> | Processus déclarant que le résultat d&#39;un nœud est obsolète.   Lorsqu&#39;un paramètre est ajusté, le nœud hébergeant ce paramètre et tous les nœuds en aval sont invalidés. Ils doivent donc être [évalués](#evaluation) et [rendus](#rendering) à nouveau. |

## M

|  |  |
| --- | --- |
| <b><span id="material"></span>Matière</b> | Ensemble des propriétés et des comportements de la matière dans l&#39;espace, qui comprend les surfaces et les volumes. L’apparence d’une entité dans l’espace 3D est définie par sa matière.   Les matériaux peuvent être définis de différentes manières et toutes les définitions ne prennent pas en charge toutes les propriétés telles que la réfraction, l’anisotropie ou le reflet. Un [shader](#shader) est une implémentation particulière d&#39;une définition de matériau.   <b>Important :</b> le terme « matériau » est un *terme générique* utilisé pour désigner diverses choses, notamment :<ul data-preserve-html="true"> <li data-preserve-html="true">L&#39;[ombrage](#shader) utilisé pour calculer l&#39;apparence d&#39;une surface ou d&#39;un volume ;</li> <li data-preserve-html="true">L&#39;ensemble de [textures](#texture) fourni à un shader ;</li> <li data-preserve-html="true">ID de matière, qui est un attribut d’une primitive 3D utilisée pour distinguer les parties qui utilisent différentes matières.</li> </ul> |
| <b><span id="mesh"></span>Maillage</b> | Objet 3D composé de [sommets](#vertex) reliés par des arêtes pour former des polygones, tels que des triangles, qui sont à leur tour assemblés en surfaces. Ces surfaces peuvent être ouvertes ou fermées.   L&#39;aspect de ces surfaces est défini par le [matériau](#material) qui leur est attribué. Le niveau de détail d&#39;un maillage dépend également fortement de son [polycount](#polycount). |
| <b><span id="metadata"></span>Métadonnées</b> | Données qui fournissent des informations sur le fichier lui-même, son environnement ou tout élément lié aux données du fichier.   Les métadonnées courantes comprennent l’auteur du fichier, les dates de création et de modification, le copyright et les illustrations de couverture.   Dans Designer, le contenu d&#39;un [package](#package) peut également contenir des métadonnées. Par exemple, un graphique de Substance générant un matériau de tissu peut contenir des métadonnées relatives aux propriétés physiques du tissu. |
| <b><span id="mipmap"></span>Mipmap</b> | Version plus petite d’une texture, souvent calculée automatiquement.   Une texture peut avoir une pyramide de versions plus petites de elle-même, qui sont interchangeables au moment de l’exécution afin que la taille la plus appropriée soit utilisée pour une qualité et des performances optimales.   Par exemple, une texture avec des détails haute fréquence affichés dans une taille plus petite produira probablement des artefacts de *moiré*. En outre, une texture plus grande implique probablement plus de [échantillons de texture](#texture-sampling).   Le terme « mipmap » provient de la technique de mappage MIP, où MIP signifie « *multum in parvo* » latin, ce qui signifie « beaucoup de choses dans un petit endroit ». |

## N

|  |  |
| --- | --- |
| <b><span id="node"></span>Nœud</b> | Objet dans un graphique qui effectue des calculs et génère un ou plusieurs résultats.   Le résultat est contrôlé à l’aide de paramètres d’entrée. Ces paramètres peuvent être répertoriés en tant que commandes dans le dock Propriétés ou en tant que connecteurs d&#39;entrée sur le nœud lui-même.   Il existe deux catégories principales de nœuds : [nœuds atomiques](#atomic-node) et nœuds d&#39;instance. |
| <b><span id="noise"></span>Bruit</b> | Image non figurative représentant une distribution aléatoire ou pseudo-aléatoire de formes et de couleurs. Les bruits sont souvent utilisés pour ajouter des variations aux surfaces ou aux déformations.   La bibliothèque de nœuds de Designer comprend une grande collection de générateurs de bruit, tels que [Taches BnW](../compositing-graphs/nodes-reference-for-com/node-library/texture-generators/noises/bnw-spots-2/bnw-spots-2.md), [Nuages](../compositing-graphs/nodes-reference-for-com/node-library/texture-generators/noises/clouds-2/clouds-2.md), [Bruit de Perlin](../compositing-graphs/nodes-reference-for-com/node-library/texture-generators/noises/perlin-noise/perlin-noise.md) ou [Voronoi](../compositing-graphs/nodes-reference-for-com/node-library/texture-generators/noises/voronoi/voronoi.md). |
| <b><span id="normal"></span>Normal</b> | En informatique 3D, la normale d&#39;une surface est un vecteur [normalisé](#normalization) perpendiculaire à cette surface et partant de cette surface vers l&#39;extérieur.   Ce vecteur représente l&#39;orientation d&#39;une surface dans l&#39;espace 3D et est utilisé pour [l&#39;ombrage](#shader) de cette surface en fonction des lumières et de la perspective de la caméra de la scène.   Une texture de [texture normale](#normal-map) peut être appliquée à une surface pour modifier ses normales et ajouter des détails. |
| <b><span id="normal-map"></span>Mappage normal</b> | Texture appliquée sur une surface pour modifier ses normales.   Il est le plus souvent utilisé pour simuler des détails qu&#39;il serait inefficace d&#39;inclure dans la géométrie d&#39;un modèle. L&#39;utilisation d&#39;une telle map permet d&#39;avoir des normales par texel en plus des normales par sommet, ce qui donne plus d&#39;informations de surface et donc plus de détails de surface.   Les coordonnées X, Y et Z des vecteurs normaux sont codées respectivement dans les canaux rouge, vert et bleu de la carte. Selon l&#39;API graphique ciblée ([DirectX](#directx) ou [OpenGL](#opengl)), la couche verte peut être inversée. |
| <b><span id="normalization"></span>Normalisation</b> | Processus de remappage d&#39;une plage de valeurs sur la plage [0, 1], où la valeur d&#39;entrée la plus élevée est remappée à 1,0 et la valeur d&#39;entrée la plus basse est remappée à 0,0.   Pour les vecteurs, la normalisation consiste à ajuster la longueur (ou « amplitude ») du vecteur à une valeur de 1,0. |

## O

|  |  |
| --- | --- |
| <b><span id="opengl"></span>OpenGL</b> | Une API graphique 3D largement utilisée dans le développement de jeux vidéo et d’autres industries 3D.   OpenGL place l&#39;origine d&#39;une texture, c&#39;est-à-dire sa coordonnée (0, 0), en *bas à gauche*, (Y-haut), tandis que l&#39;API [DirectX](#directx) la place en *haut à gauche* (Y-bas).   Cela signifie qu&#39;une carte normale OpenGL a un *canal vert inversé* par rapport au canal DirectX. En effet, le canal vert héberge la coordonnée Y des vecteurs normaux. |
| <b><span id="openusd"></span>OpenUSD</b> | Voir [USD](#usd). |
| <b><span id="output-format"></span>Format de sortie</b> | [Paramètre de base](#base-parameter) des nœuds dans un graphique de Substance qui décrit le [nombre de bits par pixel](#bit-depth) du nœud. |
| <b><span id="output-size"></span>Taille de sortie</b> | [Paramètre de base](#base-parameter) des nœuds dans un graphique de Substance qui décrit la [résolution](#resolution) du nœud.   Pour en savoir plus sur la taille de sortie, consultez cette [page dédiée](../compositing-graphs/output-size/output-size.md). |

## P

|  |  |
| --- | --- |
| <b><span id="package"></span>Package</b> | Un fichier Substance 3D ([SBS](#sbs-file)) est appelé package, dans le sens où il s&#39;agit d&#39;un conteneur de ressources : graphes, [bitmaps](#bitmap), [scènes 3D](#three-d-scene), etc. Un package stocke également les chemins d&#39;accès à ses [dépendances](#dependency) ainsi que les [métadonnées](#metadata). |
| <b><span id="pattern"></span>Motif</b> | Image qui doit être utilisée comme modèle ou référence pour produire une autre image.   Dans la plupart des cas, un motif est une image destinée à être répétée (par exemple, mosaïque, dispersée de manière aléatoire ou agencée selon un ensemble de règles). |
| <b><span id="pixel-ratio"></span>Rapport de pixels</b> | Ce [paramètre de base](#base-parameter) contrôle la compensation du rapport L/H de l&#39;image au niveau des pixels. En d’autres termes : si la taille de pixel doit être compensée pour conserver un format carré dans une image non carrée.   Le paramètre est utilisé par les filtres non locaux, c’est-à-dire les filtres qui utilisent les valeurs des pixels voisins pour calculer la valeur d’un pixel. |
| <b><span id="pixel-size"></span>Taille de pixel</b> | Ce paramètre de base définit la taille horizontale et verticale d’un pixel.   Il agit comme un multiplicateur pour les filtres non locaux, c’est-à-dire les filtres qui utilisent les valeurs des pixels voisins pour calculer la valeur d’un pixel. |
| <b><span id="polycount"></span>Polycount</b> | Quantité de polygones d&#39;un [filet](#mesh) 3D. En effet, polycount est abrégé en « polygone count ».   Plus de polygones permettent de modéliser des détails plus fins. Les maillages à faible polycount sont appelés «low-poly», tandis que les polycount plus élevés sont appelés «high-poly». |
| <b><span id="primary-input"></span>Entrée principale</b> | Connecteur d&#39;entrée d&#39;un [nœud d&#39;instance](#instance-node) à partir duquel ce nœud hérite de ses [valeurs de paramètre de base](#base-parameter).   L&#39;entrée principale est marquée par un petit point dans son connecteur et le suffixe &#39;(Primary) dans son libellé.   Lorsque vous utilisez des nœuds avec plusieurs entrées, il est *fortement* recommandé de faire attention à celle de leurs entrées qui est la principale et à son impact sur [l&#39;héritage](#inheritance) sur l&#39;ensemble du graphique. |
| <b><span id="procedural"></span>Procédural</b> | Caractéristique d&#39;une donnée ou d&#39;un artefact à créer en suivant un algorithme informatique plutôt que manuellement.   Designer utilise un workflow procédural où l’algorithme est conçu comme un graphique de nœuds.     Les processus procéduraux permettent des itérations plus rapides, car les variations et les ajustements peuvent être générés rapidement en modifiant l’algorithme et ses paramètres.   Lorsque le résultat est entièrement produit par l&#39;algorithme, ce résultat est appelé familièrement « 100% procédural ». La génération procédurale est parfois raccourcie en &#39;proc-gen&#39;.   La plupart des générateurs de la bibliothèque de nœuds Designer sont procéduraux à 100 %, car ils ne nécessitent aucune image d’entrée pour produire un résultat. |
| <b><span id="publishing"></span>Publication (SBSAR)</b> | Dans Designer, la publication fait référence à l&#39;exportation d&#39;un [package](#package) sous la forme d&#39;un fichier d&#39;archive SBSAR qui inclut des versions [compilées](#compilation) des graphiques, leurs ressources ([bitmaps](#bitmap), polices, etc.), leurs paramètres prédéfinis ainsi que leurs [métadonnées](#metadata).   Le fichier SBSAR résultant peut ensuite être distribué et utilisé dans d&#39;autres applications Substance 3D ou applications tierces via un [module externe Substance 3D](https://substance3d.adobe.com/plugins/). |

| <b><span id="rendering"></span>Rendu </b>(Vue 3D) | Processus de calcul d&#39;une image en fonction des données d&#39;entrée, à l&#39;aide d&#39;un programme tel qu&#39;un [moteur de rendu](#renderer). |

Plus de pixels permettent de représenter des détails plus fins.   Dans les graphiques de Substance, la résolution d&#39;une image bitmap calculée par un [nœud](#node) est contrôlée par le paramètre de base [Taille de sortie](#output-size) [&#x200B; du nœud.](#base-parameter) |
| <b><span id="roughness"></span>Rugosité</b> | Canal d&#39;un [matériau](../glossary/glossary.md) défini à l&#39;aide du modèle de rugosité métallique PBR [ombrage](../glossary/glossary.md). La rugosité désigne la rugosité d&#39;une surface, c&#39;est-à-dire les variations microscopiques de l&#39;height, également appelées *microfacettes*.   Une forte rugosité donne un aspect mat, tandis qu’une faible rugosité donne un aspect lisse et brillant.   C&#39;est l&#39;inverse de [brillance](#glossiness). |

| <b><span id="sbs-file"></span>Fichier SBS</b> | SBS signifie « fichier Substance 3D ». Ce fichier est utilisé pour stocker des projets Substance 3D Designer. Ses données utilisent le format [XML](#xml). Voir [pack](#package). |

Ce fichier d&#39;archive est utilisé pour stocker les graphiques Substance 3D Designer compilés et les ressources dont ils ont besoin ([bitmaps](#bitmap), polices, etc.).   SBSAR est le format de fichier principal utilisé pour distribuer des graphiques de Substances prêts à être utilisés par d’autres applications Substance 3D et modules Substance 3D.   Les graphiques stockés dans les fichiers SBSAR étant compilés, ils ne peuvent pas être chargés et modifiés dans Substance 3D Designer. Les fichiers SBSAR peuvent toutefois être ouverts à l&#39;aide de [7Zip](https://www.7-zip.org/) pour récupérer leurs paramètres, paramètres prédéfinis et métadonnées dans un fichier [XML](#xml) incorporé. |
| <span id="sdf"></span><b>SDF</b> | Voir [Champ Distance signée](#signed-distance-field). |
| <b><span id="shader"></span>Nuanceur</b> | Programme qui calcule l&#39;apparence d&#39;une surface ou d&#39;un volume en fonction de ses propriétés de [matériau](#material), de la lumière qu&#39;elle reçoit et de l&#39;endroit d&#39;où elle est vue. Un shader est une implémentation particulière d&#39;une définition de matériau.   Des textures peuvent être fournies à un shader pour piloter son comportement. Des valeurs brutes peuvent également être utilisées. Dans la [vue 3D](../interface/3d-view/3d-view.md), accédez au menu « Matières » pour voir quel nuanceur est utilisé par un matériau dans la scène actuelle. Le menu vous permet également d&#39;accéder aux [propriétés du shader](../interface/3d-view/3d-view.md) et aux textures et valeurs actuellement utilisées par le shader.   &#39;Shader&#39; est parfois utilisé de manière interchangeable avec &#39;[Material](#material)&#39;. |
| <span id="sheen"></span><b>Reflet</b> | L’aspect brillant ou brillant d’un tissu.   Ce terme est largement utilisé dans l&#39;industrie textile pour décrire une propriété réfléchissante qui ajoute une subtile luminosité colorée. |
| <b><span id="signed-distance-field"></span>Champ de distance signé (SDF)</b> | <p>Un champ de distance signé est une fonction mathématique qui définit une surface dans un espace 3D en calculant la distance entre un point quelconque de l&#39;espace et le point le plus proche de la surface.</p><p>Pour en savoir plus sur le concept et son utilisation dans Designer, cliquez ici : [Utilisation des Fonctions SDF](../function-graphs/nodes-reference-for-fun/function-node-library/function-nodes-sdf-functions/working-with-sdf-functions.md#what-is-an-sdf-function).</p> |
| <b><span id="spline"></span>Spline</b> | Généralement, il s’agit d’une courbe modélisée à l’aide d’une fonction mathématique qui permet de tracer des formes nettes et lisses à n’importe quelle résolution. Designer utilise une approximation avec perte codée dans une texture à l’aide d’un format de données personnalisé.   Les splines offrent des commandes intuitives pour la longueur et la trajectoire, incluent d&#39;autres données telles que le thickness et l&#39;height, et offrent un accès facile à la distance et à la direction à n&#39;importe quel point le long d&#39;elles.   Ces qualités en font un outil puissant pour dessiner et texturer. |
| <b><span id="static-parameter"></span>Paramètre statique</b> | Paramètre dont la valeur ne peut pas être modifiée.   Contrairement aux [paramètres dynamiques](#dynamic-parameter), les paramètres statiques ne peuvent pas être modifiés à la volée lorsque le graphique est compilé dans un fichier SBSAR. Ils peuvent être affichés et modifiés dans Designer uniquement lors de la création du graphique.   Le mode Aperçu masquera ces paramètres dans certains cas, car il vise à correspondre le plus possible au comportement des fichiers SBSAR publiés.   Une liste de paramètres statiques est disponible [ici](../compositing-graphs/manage-parameters/exposing-a-parameter/exposing-a-parameter.md). |
| <b><span id="subgraph"></span>Sous-graphe</b> | Graphique utilisé dans un autre graphique comme [nœud d&#39;instance](#instance-node). |
| <b><span id="substance-engine"></span>Substance Engine</b> | Une technologie propriétaire développée par l&#39;équipe Substance 3D, en charge du calcul des images en effectuant une grande quantité de transformations, d&#39;effets et de composition des images d&#39;entrée, de manière très efficace.   La Substance Engine implémente et calcule les [nœuds atomiques](#atomic-node) de Designer.   Le moteur est implémenté via différents backends, selon la plateforme sur laquelle il s&#39;exécute : CPU, GPU et système d&#39;exploitation. Dans Designer, les moteurs principaux peuvent être basculés en accédant à [Outils > Changer de moteur](../interface/the-main-toolbar/the-main-toolbar.md).   Certains back-ends offrent des performances nettement supérieures à d’autres (par exemple, le back-end GPU est beaucoup plus rapide que le processeur) et les résultats peuvent être légèrement différents entre les back-ends. |
| <b><span id="substance-graph"></span></b><b>Graphique de Substance</b> (ou graphique de composition de Substance) | Graphique produisant une ou plusieurs [images bitmap](#bitmap).   Un graphique de Substance peut être utilisé à diverses fins : - produire un ensemble d’images bitmap qui sont des textures décrivant un matériau ; - effectuer un traitement d’image sur une ou plusieurs entrées bitmap, en tant que filtre ; - générer des bruits, des motifs ou des données brutes, en tant que générateur. |

## T

|  |  |
| --- | --- |
| <b><span id="tessellation"></span>Crénelage</b> | Dans l’infographie, la facettisation est le processus consistant à subdiviser une surface en plusieurs polygones, souvent des triangles.   Ce processus peut être effectué à l&#39;exécution pour augmenter dynamiquement la quantité de polygones d&#39;un modèle 3D, souvent en association avec des [cartes de displacements](#displacement) et des [cartes de normales](#normal-map) pour modéliser des détails plus fins à l&#39;aide des polygones ajoutés. |
| <b><span id="texel"></span>Texel</b> | Unité d&#39;information d&#39;une [texture](#texture), de la même manière qu&#39;un pixel est l&#39;unité d&#39;information d&#39;une image. |
| <b><span id="texture"></span>Texture</b> | Image utilisée pour représenter des graphiques, décrire les propriétés de [matière](#material) d&#39;une surface en fournissant des valeurs à un [shader](#shader) et coder des données brutes dans ses [texels](#texel).   Les textures sont des objets qui peuvent être décompressés et manipulés très efficacement par les GPU. Dans la plupart des cas, cette efficacité nécessite que les textures utilisent une puissance de deux résolutions, par exemple 1 024 x 1 024, 4 096 x 4 096, 512 x 256, etc. |
| <b><span id="texture-sampling"></span>Échantillonnage de texture</b> | Acquisition de la valeur d&#39;une [texture](#texture) à un emplacement spécifique.   Certains algorithmes nécessitent de nombreux échantillons pour comparer des valeurs, les moyenner ou d&#39;autres opérations.   Si un échantillon n’est pas effectué exactement au centre d’un pixel, il existe deux options dans Designer pour la valeur à acquérir :<ul data-preserve-html="true"> <li data-preserve-html="true"><b>Le plus proche :</b> la valeur du pixel le plus proche en fonction de son centre</li> <li data-preserve-html="true"><b>Filtrage bilinéaire :</b> valeur de l&#39;interpolation entre les pixels voisins horizontalement et verticalement, où les pixels plus proches ont plus de poids.</li> </ul> |
| <b><span id="tiling"></span>Mosaïque</b> | Répétition d’une image horizontalement, verticalement ou les deux, sans coutures visibles ni discontinuité visuelle.   Designer propose beaucoup de [nœuds](#node) qui génèrent [bruits](#noise) ou [motifs](#pattern) à partir de cette vignette. De même, de nombreux nœuds de [filtre](#filter) sont conçus pour traiter les images tout en préservant la juxtaposition. |

## H

|  |  |
| --- | --- |
| <b><span id="usage"></span>Utilisation (sortie)</b> | Dans les graphiques de Substances, une utilisation est un attribut d&#39;un nœud [Sortie](../compositing-graphs/nodes-reference-for-com/atomic-nodes/output/output.md) utilisé pour indiquer à l&#39;application comment connecter une [texture](#texture) à l&#39;[ombrage](#shader) dans la [vue 3D](../interface/3d-view/3d-view.md).   Lors de l’application d’un graphique de Substance à la vue 3D, toutes les sorties sont connectées au nuanceur en fonction des utilisations correspondantes. Par exemple, « couleur de base » à « couleur de base », « rugosité » à « rugosité », et ainsi de suite.   Les utilisations sont également utilisées pour faire correspondre les connecteurs lors de l&#39;utilisation des [modes de création de liens](../interface/the-graph-view/link-creation-modes/link-creation-modes.md) &#39;Matériau&#39; et &#39;Matériau compact&#39;. |
| <b><span id="udim"></span>UDIM</b> (tuiles UV) | Norme permettant de diviser l&#39;espace [UV](#uv) en carreaux dotés d&#39;un identifiant numérique unique, qui permet d&#39;attribuer une texture différente à chaque carreau.   Les workflows UDIM sont courants dans les pipelines d’effets spéciaux, où les ressources haute fidélité nécessitent tellement de détails que plusieurs textures haute résolution sont nécessaires. Dans ce cas, les [UV](#uv)s de la ressource sont disposés sur plusieurs UDIM (ou tuiles UV).   Designer prend en charge les workflows UDIM et peut attribuer un graphique de Substance différent par UDIM. |
| <b><span id="usd"></span>USD</b> (ou OpenUSD) | L&#39;[Universal Scene Description](https://openusd.org/release/index.html) (USD) est un format de description de scène 3D conçu par Pixar pour l&#39;interopérabilité et l&#39;exchange des données entre les applications et les plateformes.   Les fichiers USD incluent la définition des données utilisées dans une scène, ainsi que la composition de cette scène et tout ce qu&#39;elle implique : modèles, matériaux, caméras, animations, simulations, etc. Un fichier USD peut inclure tout type de données, à condition que l&#39;application ait accès au module USD qui lui permet de lire et d&#39;utiliser ces données correctement.   L&#39;Adobe est [impliqué dans l&#39;Alliance for OpenUSD](https://blog.adobe.com/en/publish/2023/08/01/powering-3d-interoperability-continued-collaboration-through-openusd), un consortium d&#39;acteurs de l&#39;industrie 3D qui contribuent activement au développement et à la normalisation du format. |
| <b><span id="uv"></span>UV</b> | Les UV représentent un modèle 3D dans un espace 2D. Ils sont utilisés pour mapper des images 2D de l’espace 2D sur la surface du modèle dans l’espace 3D.   Le processus de création d’UV est souvent décrit comme une découpe de contours dans le modèle pour le déplier et le mettre à plat. |
